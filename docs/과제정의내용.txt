차기 유사사례 재활용

CR 유형(신규/변경/DB 변경)에 따라 분기 — LangGraph DAG 상태머신. 검수 지점 HITL 중단점, 오류 시 재시도·에스컬레이션 자가 보정.

개선 목표 (3개월)
1단계(~1개월) : 신규 화면 개발 CR 적용, KPI 기준선 측정
2단계(~2개월) : 기능 변경·DB 변경 확대, 게이트·RAG 파라미터 튜닝
3단계(~3개월) : 누락률·Recall@5·분석 시간 목표 달성 검증
AI 기술 활용

각 기술은 Pain Point 해결을 위해 선택되었으며, 단순 API 호출이 아닌 직접 구현으로 최적화한다.

①

RAG — 하이브리드 검색 + Reranker  【P2 해결】

코드(Python AST 함수·클래스 단위) · 문서(Markdown 헤딩 단위) · CR 이력(건 단위) 파일 유형별 청크 전략 직접 설계. BM25 + Dense 임베딩을 가중 RRF(BM25 0.3 / Dense 0.7)로 결합하고 Cross-encoder Reranker로 도메인 적합도 보정.

②

LangGraph Stateful Agent Orchestration  【P1·P3 해결】

CR 유형별 Conditional Edge 분기 · 단계 간 State 전달 · HITL 중단점(분석 리포트 검수) · 에러 복구 노드(재시도·에스컬레이션)를 DAG로 직접 구성. 단순 Chain으로는 게이트·HITL·자가 보정 구현 불가.

③

Tool-using Agent — 외부 시스템 실시간 연동  【P1 해결】

요구사항 구체화(GitHub·Confluence·두드림 Tool Calling) · 영향도 분석(Oracle ALL_DEPENDENCIES·ALL_TAB_COLUMNS 조회 + 코드 검색). 순수 LLM 호출로는 사내 메타데이터 실시간 연동 불가.

④

확정 규칙 기반 검증 게이트(Verifier)  【P1 해결】

영향 누락·정합성 점검을 LLM 판단 없이 Config 규칙으로 확정 검증 → 100% 재현 가능한 누락 차단. 비결정적 LLM에 맡길 경우 게이트 통과 신뢰성 보장 불가.

⑤

이력 기반 자기 개선 루프  【P2·P3 해결】

검수 완료 CR 실적을 이력 저장소에 구조화 저장 → 벡터 컬렉션 재색인으로 검색 정확도 점진 향상. HITL 승인/반려 피드백을 Reranker 학습 데이터로 축적.
